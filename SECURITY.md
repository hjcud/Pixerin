# Security reporting

Supported development line: **0.22.0-beta.1**. No stable support schedule or
automatic security updater is promised during beta.

For a suspected vulnerability, use the repository's **Security → Report a
vulnerability** option when private reporting is available. If it is unavailable,
open a minimal issue asking the maintainer for a private reporting channel; omit
exploit instructions, credentials, artwork and private paths from that request.
No private email address or reporting SLA has been established here.

Include the affected version, platform, a minimal reproduction using disposable
data, expected/observed behavior and relevant sanitized logs in the agreed private
channel. Do not upload API keys, sign-in files, full app profiles or personal art.

Local custom scripts and imported files should come from sources you trust.
Keep the complete application distribution and dependency notices together.
See [AI data handling](DATA_HANDLING.md) for transmitted context, credential
storage and the Codex metadata-only inspection boundary.
